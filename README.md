# StudyQuest

**StudyQuest** — чат-бот и Mini App в MAX для студентов одной учебной группы. Сервис собирает домашние задания, лабораторные работы и напоминание о экзаменах в одном месте, напоминает о сроках, поддерживает групповые опросы и превращает текстовые сообщения в проверяемые черновики квестов.

> **Техническая информация для проверки**

## Быстрый запуск через Docker

### 1. Подготовьте окружение

Создайте корневой `.env` рядом с `docker-compose.yml`:

```env
POSTGRES_DB=max_hackathon
POSTGRES_USER=postgres
POSTGRES_PASSWORD=<STRONG_PASSWORD>

DB_CONNECT_URL=postgres://postgres:<STRONG_PASSWORD>@postgres:5432/max_hackathon
FRONTEND_URL=<URL_MINI_APP_HTTPS_OR_LOCAL>
VITE_BACKEND_URL=<URL_API_HTTPS_OR_LOCAL> (обычно совпадает с FRONTEND_URL при разработки)
MAX_BOT_TOKEN=<MAX_BOT_TOKEN>
JWT_SECRET=<AT_LEAST_32_CHARACTERS_SECRET>

# Для GIGACHAT
GIGACHAT_AUTHORIZATION_KEY=<GIGACHAT_AUTHORIZATION_KEY>
GIGACHAT_SCOPE=GIGACHAT_API_PERS работаем от физ. лица
GIGACHAT_MODEL=GigaChat-2 модель
GIGACHAT_TIMEOUT_MS=15000 таймаут
```

> `DEV_USER_ID` не нужен и не используется в production Docker Compose. Он предназначен только для локального режима разработки.

### 2. Запустите все компоненты одной командой

```bash
docker compose -f docker-compose.yml up -d
```

## Используемые порты

| Компонент | Порт | URL |
| --- | --- | --- |
| Frontend | `5173` | `http://localhost:5173` |
| Backend (Express API) | `3000` | `http://localhost:3000`; доступен только на localhost при запуске через Docker |
| Adminer | `8080` | `http://localhost:8080`; доступен только на localhost |
| PostgreSQL | `5432` | В основном Docker Compose доступен только внутри Docker-сети как `postgres:5432`; в режиме локальной разработки проброшен на `localhost:5432` |

> Для публикации на сервере команды используется ещё один nginx и порты 80, 443 для http/https.

### Остановка и повторный запуск

```bash
# Остановить контейнеры
 docker compose down

# Остановить и удалить данные PostgreSQL
 docker compose down -v

# Повторно собрать и запустить
 docker compose -f docker-compose.yml up -d
```

## Проблема и целевая аудитория

**Приоритетный сегмент:** студенты одной учебной группы колледжа или вуза, которые координируют домашние задания, лабораторные работы, подготовку к экзаменам и организационные вопросы в общем чате.

Сегодня задания, сроки и договорённости часто теряются в переписке: студенту приходится вручную переносить их в заметки, уточнять дедлайны и отдельно напоминать одногруппникам. Это приводит к пропущенным срокам, повторным вопросам и лишней ручной координации.

**Гипотеза:** если студент может превратить сообщение из MAX в проверяемый черновик задания, опубликовать его для группы и видеть дедлайны с уведомлениями в Mini App, то количество пропущенных заданий и ручных уточнений снизится.

## Что даёт продукт

- единый журнал личных и групповых заданий;
- сроки, статусы выполнения и Pomodoro-сессии;
- групповые опросы для организационных вопросов;
- уведомления в Mini App и в чате MAX о новых заданиях;
- геймифицированный прогресс: XP, уровень, INT/END/REP;
- AI-черновик задания по обычному сообщению в боте с обязательным подтверждением пользователя;
- серьёзный и игровой режимы интерфейса, сохраняемые в профиле.

## Основной пользовательский сценарий

1. Студент открывает чат с ботом StudyQuest в MAX и отправляет `/start`.
2. Бот собирает группу, имя и согласие с условиями, после чего открывает Mini App кнопкой **«Открыть StudyQuest»**.
3. В Mini App студент проходит приветствие, выбирает серьёзный или игровой стиль и видит задания своей группы.
4. Студент отправляет боту текст: «Лабораторная по информатике, сдать в пятницу до 18:00».
5. Бот запрашивает согласие на передачу текста в GigaChat для формирования **черновика**, показывает индикатор ожидания и задаёт вопросы о недостающих данных.
6. Студент проверяет карточку черновика, при необходимости выбирает поле для изменения, затем явно нажимает **«Создать квест»**.
7. Задание появляется в журнале группы; участники получают уведомление в Mini App и в MAX.
8. Каждый участник отмечает своё выполнение. При первом завершении сервер начисляет XP и обновляет уровень/характеристики.

Задание **не создаётся автоматически** из ответа LLM: пользователь подтверждает передачу текста и затем отдельно подтверждает публикацию квеста.

### Правила начисления XP (опыта)

| Тип квеста | Награда |
| --- | ---: |
| Домашняя работа | 100 XP |
| Лабораторная работа | 150 XP |
| Подготовка к экзамену | 200 XP |
| Опрос группы | 50 XP |
| Личное задание | 100 XP |

Награда рассчитывается сервером и выдаётся один раз на пользователя и квест. Повторные запросы не дублируют XP.

## Архитектура

```text
MAX Bot ──┐                         ┌── GigaChat OAuth + Chat API
          ├── Express API ──────────┤
Mini app ─┘           │             └── MAX Bot notifications
                       │
                   PostgreSQL
                       │
       users / groups / quests / progresses /
       polls / votes / notifications / progression events
```

### Компоненты

- **`backend/`** — Express 5, Sequelize, PostgreSQL, MAX Bot API, JWT и GigaChat-интеграция.
- **`frontend/`** — Vue 3, Pinia, Vue Router, Vue I18n, Tailwind CSS и локальные DiceBear 10-аватары.
- **PostgreSQL** — Таблицы пользователей, групп, квестов, прогресса, опросов, уведомлений, XP и настроек интерфейса.
- **GigaChat** — формирует только структурированный черновик.
- **NGINX** - Reverse-прокси. (Так же отвечает за ssl на сервере команды)

## GigaChat: данные и ограничения

AI-черновик — внешняя интеграция, требующая `GIGACHAT_AUTHORIZATION_KEY`. Если ключ не настроен или GigaChat недоступен, квест не создаётся, а бот объясняет, что пользователь может повторить попытку или создать задание через Mini App.

## Проверка основного сценария

1. Откройте MAX-бот `<URL_MAX_BOT>` и выполните `/start`.
2. Зарегистрируйте тестового пользователя: укажите группу и имя.
3. Нажмите **«Открыть StudyQuest»**.
4. Выберите стиль интерфейса и откройте журнал заданий.
5. Создайте групповой квест с дедлайном или отправьте текст задания боту.
6. Во втором пользователе той же группы проверьте уведомление в MAX и в Mini App.
7. Отметьте задание выполненным и убедитесь, что отображаются XP, уровень и характеристики.
8. Создайте опрос группы, проголосуйте вторым пользователем и проверьте результаты.

## Известные ограничения MVP

- Сессии бота хранятся в памяти процесса (Рестарт сервера прерывает незавершённый диалог регистрации или работы с GigaChat).
- Уведомление в Mini App является гарантированным каналом; отправка в MAX выполняется best-effort и может не дойти, если пользователь заблокировал бота или MAX временно недоступен.
- AI-парсинг предназначен для черновиков задач и не для чего более.
- Для production вместо `sequelize.sync({ alter: true })` необходимо использовать миграции БД.
